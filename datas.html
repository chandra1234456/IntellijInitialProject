🎯 1. ViewModel - Core Concepts

1 What is ViewModel in Android? Why is it important?

ViewModel is an Android Architecture Component that stores UI-related data across configuration changes (screen rotations). It survives activity/fragment recreation, preventing data loss and reducing memory leaks.

class MyViewModel : ViewModel() {
    private val _data = MutableLiveData<String>()
    val data: LiveData<String> = _data

    fun loadData() {
        _data.value = "Persisted across rotation"
    }
}
2 What is the lifecycle of ViewModel? When is it destroyed?

ViewModel exists from first request until the scope (Activity/Fragment) is finished permanently (onDestroy called and not due to config change). For Activity, it's cleared on finish(). For Fragment, when detached and removed.

3 How to share data between fragments using ViewModel?

Use activity-scoped ViewModel. Both fragments get the same ViewModel instance via requireActivity() or parent fragment scope.

val viewModel = ViewModelProvider(requireActivity()).get(SharedViewModel::class.java)
// Fragment A and Fragment B can now observe and update the same ViewModel
4 What is ViewModelFactory? When do you need it?

ViewModelFactory is used when ViewModel has constructor parameters. It's a factory pattern to create ViewModel instances with custom dependencies.

class MyViewModelFactory(private val repo: Repository) : ViewModelProvider.Factory {
    override fun <T : ViewModel> create(modelClass: Class<T>): T {
        return MyViewModel(repo) as T
    }
}
5 What is onCleared() method in ViewModel?

onCleared() is called when ViewModel is about to be destroyed. Use it to cancel coroutines, close resources, or clean up to prevent memory leaks.

override fun onCleared() {
    super.onCleared()
    job.cancel() // Cancel coroutines
}

📡 2. LiveData & MutableLiveData

6 What is LiveData? How is it different from regular observable?

LiveData is lifecycle-aware observable data holder. It only updates active observers (STARTED/RESUMED), preventing crashes and reducing unnecessary updates. Unlike RxJava, it automatically handles lifecycle.

7 What is MutableLiveData? How is it different from LiveData?

MutableLiveData extends LiveData and exposes public setValue() (main thread) and postValue() (background thread) methods. LiveData is read-only, MutableLiveData is read-write.

private val _counter = MutableLiveData<Int>(0)  // mutable internal
val counter: LiveData<Int> = _counter           // read-only exposed
8 Difference between setValue() and postValue()?

setValue() must be called on main thread, updates immediately. postValue() can be called from background thread, posts update to main thread. postValue() merges multiple calls - only last value is delivered.

9 What is Transformations.map() and Transformations.switchMap()?

map() transforms LiveData values. switchMap() returns a new LiveData based on value changes, useful for triggering repository calls.

val userId: LiveData<String> = ...
val user = Transformations.switchMap(userId) { userId ->
    repository.getUser(userId)  // Returns LiveData<User>
}
10 What is MediatorLiveData? Give use case.

MediatorLiveData can observe multiple LiveData sources and react when any of them changes. Use case: combining data from multiple sources (database + network).

val mediator = MediatorLiveData<String>()
mediator.addSource(liveData1) { value -> mediator.value = combine(value, liveData2.value) }
mediator.addSource(liveData2) { value -> mediator.value = combine(liveData1.value, value) }

🌊 3. Flow - Cold Streams

11 What is Flow in Kotlin? How is it different from LiveData?

Flow is a cold asynchronous stream that emits values sequentially. Unlike LiveData, Flow is not lifecycle-aware by default (needs repeatOnLifecycle), but offers more operators and coroutine support.

12 What are cold flows vs hot flows?

Cold flows (regular Flow) start emitting when collected, each collector gets all emissions. Hot flows (SharedFlow/StateFlow) emit independently of collectors, sharing emissions among multiple collectors.

13 How to collect Flow in Android safely?

Use repeatOnLifecycle to collect Flow lifecycle-aware. This cancels collection when lifecycle goes below STARTED.

lifecycleScope.launch {
    repeatOnLifecycle(Lifecycle.State.STARTED) {
        viewModel.myFlow.collect { value -> updateUI(value) }
    }
}
14 What are Flow operators like map, filter, catch, retry?

Flow provides rich operators: map (transform), filter (conditional), catch (error handling), retry (retry on failure), debounce (throttle), distinctUntilChanged (avoid duplicates).

flow {
    emit(repository.fetchData())
}.map { it.name }
 .filter { it.isNotEmpty() }
 .catch { e -> emit(defaultValue) }
 .retry(3)
 .collect { value -> ... }

⚡ 4. StateFlow & MutableStateFlow

15 What is StateFlow? How is it different from LiveData?

StateFlow is a hot flow that holds a single state value. It's similar to LiveData but part of coroutines, supports initial value, and doesn't have lifecycle awareness (requires manual handling).

private val _state = MutableStateFlow(LoadingState())
val state: StateFlow<UiState> = _state.asStateFlow()
16 What is MutableStateFlow and how to expose it safely?

MutableStateFlow is the mutable version with value property. Expose as read-only StateFlow using asStateFlow() to prevent external modifications.

private val _uiState = MutableStateFlow<UiState>(UiState.Loading)
val uiState: StateFlow<UiState> = _uiState.asStateFlow()
17 What is state deduplication in StateFlow?

StateFlow doesn't emit duplicate consecutive values (same equals comparison). If new value equals current value, collectors aren't notified. Prevents unnecessary UI updates.

18 How to collect StateFlow in Compose?

Use collectAsState() extension function in Jetpack Compose to collect StateFlow and recompose on changes.

val uiState by viewModel.uiState.collectAsState()

🔄 5. SharedFlow & MutableSharedFlow

19 What is SharedFlow? When to use it vs StateFlow?

SharedFlow is a hot flow that can emit multiple values without holding a single state. Use for one-time events (toasts, navigation) or multiple values where only the latest matters isn't required.

20 What is MutableSharedFlow? Explain replay, extraBufferCapacity, onBufferOverflow.

MutableSharedFlow parameters: replay (number of past values to replay), extraBufferCapacity (additional buffer), onBufferOverflow (SUSPEND, DROP_OLDEST, DROP_LATEST).

private val _events = MutableSharedFlow<UiEvent>(
    replay = 0,
    extraBufferCapacity = 10,
    onBufferOverflow = BufferOverflow.DROP_OLDEST
)
21 How to emit events with SharedFlow for navigation?

Use SharedFlow for one-time events like navigation, snackbar, or dialogs. Collect in fragment and trigger action.

// ViewModel
private val _navigationEvent = MutableSharedFlow<String>()
val navigationEvent = _navigationEvent.asSharedFlow()

fun onButtonClick() {
    viewModelScope.launch {
        _navigationEvent.emit("details_screen")
    }
}

📊 6. Comparisons & Decision Making

22 LiveData vs StateFlow: Which one to use?

Use LiveData for simple cases, Java codebase, or when you need automatic lifecycle handling. Use StateFlow when using coroutines, Compose, or need advanced operators. Modern Android recommends StateFlow + repeatOnLifecycle.

FeatureLiveDataStateFlow
Lifecycle-aware✅ Automatic❌ Need repeatOnLifecycle
Initial value❌ No✅ Required
OperatorsLimitedRich (map, filter, etc)
Coroutines supportLimited✅ First-class
23 StateFlow vs SharedFlow: When to use each?

StateFlow: UI state (data class with loading, content, error). Holds single state, deduplicates. SharedFlow: One-time events (toast, navigation, dialogs). Multiple emissions without state holding.

🎬 7. Scenario-Based Questions

S1 Scenario: User rotates screen while API call is in progress. How to prevent data loss?

Use ViewModel to store API result. API call initiated from ViewModel using coroutines. Result stored in StateFlow/LiveData. Screen rotation doesn't restart API call because ViewModel survives config change.

class MyViewModel : ViewModel() {
    private val _uiState = MutableStateFlow<UiState>(UiState.Loading)
    val uiState = _uiState.asStateFlow()

    init {
        viewModelScope.launch {
            val result = repository.fetchData()
            _uiState.value = UiState.Success(result)
        }
    }
}
S2 Scenario: Show a single Toast message when data loading completes, but avoid showing on rotation.

Use SharedFlow for one-time events. It doesn't replay after rotation (replay=0). Collect in fragment and show toast only once per emission.

private val _toastEvent = MutableSharedFlow<String>(replay = 0)
val toastEvent = _toastEvent.asSharedFlow()

// In fragment
lifecycleScope.launch {
    repeatOnLifecycle(Lifecycle.State.STARTED) {
        viewModel.toastEvent.collect { message ->
            Toast.makeText(context, message, Toast.LENGTH_SHORT).show()
        }
    }
}
S3 Scenario: Search bar with debouncing to avoid excessive network calls.

Use Flow's debounce operator on search query StateFlow.

class SearchViewModel : ViewModel() {
    private val _searchQuery = MutableStateFlow("")
    val searchQuery = _searchQuery.asStateFlow()

    val searchResults = searchQuery
        .debounce(500)  // Wait 500ms after user stops typing
        .distinctUntilChanged()
        .flatMapLatest { query ->
            repository.search(query)
        }
        .stateIn(viewModelScope, SharingStarted.WhileSubscribed(), emptyList())
}
S4 Scenario: Multiple fragments need to share data and communicate.

Use activity-scoped ViewModel with StateFlow. Fragments observe same ViewModel and update through exposed functions.

// Shared ViewModel
class SharedViewModel : ViewModel() {
    private val _selectedItem = MutableStateFlow<Item?>(null)
    val selectedItem = _selectedItem.asStateFlow()

    fun selectItem(item: Item) { _selectedItem.value = item }
}

// Fragment A (list) calls selectItem()
// Fragment B (detail) observes selectedItem

💻 8. Live Coding Examples

C1 Implement a counter using MutableStateFlowEasy
class CounterViewModel : ViewModel() {
    private val _count = MutableStateFlow(0)
    val count: StateFlow<Int> = _count.asStateFlow()

    fun increment() { _count.value++ }
    fun decrement() { _count.value-- }
}

// In Compose
@Composable
fun CounterScreen(viewModel: CounterViewModel) {
    val count by viewModel.count.collectAsState()
    Column {
        Text("Count: $count")
        Button(onClick = { viewModel.increment() }) { Text("+") }
    }
}
C2 Fetch data from repository with loading state using StateFlowMedium
sealed class UiState<out T> {
    object Loading : UiState<Nothing>()
    data class Success<T>(val data: T) : UiState<T>()
    data class Error(val message: String) : UiState<Nothing>()
}

class DataViewModel(private val repo: Repository) : ViewModel() {
    private val _uiState = MutableStateFlow<UiState<List<Item>>>(UiState.Loading)
    val uiState = _uiState.asStateFlow()

    init { fetchData() }

    fun fetchData() {
        viewModelScope.launch {
            _uiState.value = UiState.Loading
            try {
                val data = repo.getItems()
                _uiState.value = UiState.Success(data)
            } catch (e: Exception) {
                _uiState.value = UiState.Error(e.message ?: "Unknown error")
            }
        }
    }
}
C3 Convert LiveData to Flow and vice versaEasy
// LiveData to Flow
val liveData = MutableLiveData<String>()
val flow = liveData.asFlow()  // Converts to Flow

// Flow to LiveData
val myFlow = flowOf("A", "B", "C")
val liveDataFromFlow = myFlow.asLiveData()  // For lifecycle-aware observation
C4 Combine multiple StateFlows into one UI stateMedium
class CombinedViewModel : ViewModel() {
    private val _userName = MutableStateFlow("")
    private val _userAge = MutableStateFlow(0)

    val uiState = combine(_userName, _userAge) { name, age ->
        UserUiState(name = name, age = age, isValid = name.isNotBlank() && age > 0)
    }.stateIn(
        scope = viewModelScope,
        started = SharingStarted.WhileSubscribed(5000),
        initialValue = UserUiState()
    )
}

✨ 9. Best Practices & Advanced Tips

24 How to handle configuration changes with StateFlow?

Use SharingStarted.WhileSubscribed() to keep flow active while UI is subscribed. For longer retention, use SharingStarted.Eagerly but careful with resources.

val myFlow = repository.getData()
    .stateIn(
        scope = viewModelScope,
        started = SharingStarted.WhileSubscribed(5000), // Stops after 5 sec no subscribers
        initialValue = emptyList()
    )
25 What is the common mistake when using SharedFlow for events?

Using StateFlow for one-time events causes replay on rotation. Always use SharedFlow with replay=0. Also ensure events are collected in lifecycleScope with repeatOnLifecycle to avoid collecting in background.

26 How to unit test ViewModel with StateFlow?

Use runTest and collect values using first() or toList(). Create a test coroutine scope.

@Test
fun testViewModel() = runTest {
    val viewModel = MyViewModel(repo)
    viewModel.uiState.test {
        val initialState = awaitItem()
        assert(initialState is Loading)
        // Trigger action
        viewModel.loadData()
        val successState = awaitItem()
        assert(successState is Success)
    }
}
