Top 50 Android Interview Questions & Answers

Kotlin

1. Difference between val and var?
val is immutable (read-only reference), var is mutable. Use val by default for safer code and immutability.
2. What are coroutines?
Coroutines are lightweight threads used for async tasks. They avoid blocking the main thread and are lifecycle-aware. 
viewModelScope.launch {
   val data = repo.getData()
}
3. suspend function?
A function that can pause and resume without blocking a thread.
4. What is Flow?
Cold async stream emitting multiple values. Works well with Room and APIs.
5. Null safety?
Kotlin avoids NullPointerException using nullable (?) and safe calls.
6. Extension functions?
Allow adding functions to existing classes without modifying them.

Jetpack Compose

7. What is Compose?
Declarative UI toolkit where UI updates automatically based on state.
8. Recomposition?
UI redraw triggered when state changes. Only affected parts update.
9. remember?
Stores state across recompositions.
10. mutableStateOf?
Creates observable state that triggers recomposition.
11. LazyColumn?
Efficient scrolling list (like RecyclerView).
12. State hoisting?
Move state to parent to make UI reusable and testable.

MVVM + Clean Architecture

13. MVVM?
Separates UI (View), logic (ViewModel), data (Model).
14. ViewModel role?
Holds UI state and survives configuration changes.
15. Clean Architecture?
Layers: - UI - Domain (business logic) - Data
16. UseCase?
Encapsulates a single business rule.
17. Repository?
Abstracts data sources (API + DB).
18. MVVM vs MVP?
MVVM uses reactive state; MVP uses manual callbacks.

Dependency Injection

19. DI?
Inject dependencies instead of creating them manually.
20. Hilt?
Simplified DI framework built on Dagger.
21. Dagger vs Hilt?
Hilt reduces boilerplate and integrates with Android lifecycle.
22. Scope?
Defines lifecycle of dependency.
23. Singleton?
One instance for entire app lifecycle.
24. @Inject?
Requests dependency injection.

Room

25. Room?
SQLite abstraction with compile-time safety.
26. Entity?
Represents DB table.
27. DAO?
Handles DB queries.
28. Migration?
Handles schema changes without losing data.
29. Room vs SQLite?
Room is safer and easier.
30. Flow with Room?
Observes real-time DB changes.

Testing

31. Unit testing?
Test individual components in isolation.
32. Integration testing?
Test multiple components together.
33. Mockito?
Mock dependencies.
34. Robolectric?
Run Android tests on JVM without emulator.
35. Test ViewModel?
Mock repo and verify state output.
36. Mocking?
Simulate real objects in tests.

Git

37. Git?
Distributed version control system.
38. Merge vs Rebase?
Merge keeps history; rebase rewrites history.
39. Branching?
Feature-based workflow.
40. Pull request?
Request to merge code after review.
41. Conflict?
Resolve manually when changes overlap.

IoT / BLE

42. BLE?
Low-power Bluetooth communication.
43. BLE lifecycle?
Scan → Connect → Discover → Communicate.
44. GATT?
Defines BLE services & characteristics.
45. Scan?
Use BluetoothLeScanner API.
46. Disconnect handling?
Retry with backoff strategy.
47. Permissions?
Bluetooth + Location (Android 12+ specific).
48. Battery optimization?
Reduce scan intervals.
49. BLE use case?
Wearables, smart devices.
50. Biggest BLE challenge?
Unstable connections and device fragmentation.
