🧠 Kotlin Coroutines – Complete Interview Q&A

All questions from the original document — answered in depth, with practical insights.

📘 Basics

  • ❓ What are coroutines in Kotlin?
    Coroutines are lightweight concurrency primitives that allow writing asynchronous, non-blocking code sequentially. They are provided by the Kotlin runtime and suspend execution without blocking threads.
  • ❓ How are coroutines different from threads?
    Threads are OS-level, expensive (memory, context switching). Coroutines are user-level, cheap (can create millions), and they are suspendable — a thread can run many coroutines. Coroutines rely on cooperative multitasking, threads use preemptive.
  • ❓ What problem do coroutines solve?
    Callback hell, thread blocking, resource waste. They simplify async tasks like network calls, database access, UI responsiveness, and structured concurrency.
  • ❓ What is a suspending function?
    A function marked with suspend that can pause execution without blocking the underlying thread. It can only be called from another suspend function or a coroutine builder.
  • ❓ Is suspend fun a coroutine? Explain.
    No. A suspend function is a building block; it needs a coroutine scope or builder to be invoked. The coroutine is the execution context that manages suspension and resumption.

🏗️ Coroutine Builders

  • ❓ What is launch?
    Fire-and-forget coroutine builder. Returns a Job and does not return a result. Used for operations where you don't need a return value.
  • ❓ What is async?
    Builder that returns a Deferred (a subclass of Job). Used to compute a result asynchronously, call .await() to get the result.
  • ❓ Difference between launch and async?
    launch returns Job for control, no result; async returns Deferred which holds a result. Both start coroutines, but async is for parallel decomposition.
  • ❓ What is runBlocking and when should it be used?
    Bridges blocking and suspendable worlds. It blocks the current thread until all coroutines inside complete. Use in main() functions, tests, or rare cases — never in production Android/UI.

🎯 Coroutine Scope & Context

  • ❓ What is CoroutineScope?
    Defines a lifecycle for coroutines. Provides methods like launch, async and ensures structured concurrency. Coroutines started within a scope are bound by its lifetime.
  • ❓ What is CoroutineContext?
    A set of elements that define behavior of a coroutine: Job, Dispatcher, CoroutineName, and CoroutineExceptionHandler. Immutable and union of elements.
  • ❓ What is a Dispatcher?
    Determines which thread(s) a coroutine runs on. Part of CoroutineContext. Examples: Main, IO, Default, Unconfined.
  • ❓ Difference between Dispatchers.Main, IO, and Default?
    Main → UI thread (Android/Swing). IO → blocking tasks (network, disk). Default → CPU-intensive work (sorting, parsing). IO has a flexible thread pool, Default uses limited threads equal to CPU cores.
  • ❓ What happens if no dispatcher is specified?
    Inherits dispatcher from outer CoroutineScope. If none, defaults to Dispatchers.Default for coroutine builders like launch/async when no context is present.

⏸️ Suspension & Cancellation

  • ❓ What does suspension mean in coroutines?
    Pausing a coroutine without blocking a thread. When suspended, the thread executes other coroutines; later, when ready, the coroutine resumes.
  • ❓ How does delay() work internally?
    Suspend function that schedules a timer and resumes the coroutine after given time without blocking the underlying thread. Uses cancellation-aware sleep.
  • ❓ How do you cancel a coroutine?
    Call job.cancel() or cancel() on the scope. Cancellation is cooperative: coroutine must check for cancellation (suspend functions like delay, yield, or explicit isActive).
  • ❓ What is cooperative cancellation?
    Coroutines do not stop immediately; they must voluntarily respond to cancellation by checking cancellation status or calling suspend functions that throw CancellationException.
  • ❓ What is isActive?
    Extension property inside coroutine that checks if the job is still active (not cancelled or completed). Used to exit heavy loops early.

⚠️ Exception Handling

  • ❓ How are exceptions handled in coroutines?
    Depends on builder: launch propagates exceptions to the parent by default (unless a handler is used). async wraps exceptions inside Deferred and throws when .await() is called.
  • ❓ Difference between exception handling in launch and async?
    In launch, uncaught exceptions crash the scope unless handled via CoroutineExceptionHandler. For async, exceptions are caught when calling await() — otherwise silent.
  • ❓ What is CoroutineExceptionHandler?
    Optional element in context that handles uncaught exceptions in coroutines (works only for launch, not for async). Acts as global catch-all for root coroutines.
  • ❓ What happens when one coroutine fails?
    In structured concurrency (regular scope), failure of a child cancels its parent and all siblings. With supervisorScope or SupervisorJob, siblings are not cancelled.

🔗 Structured Concurrency

  • ❓ What is structured concurrency?
    Principle that coroutines are launched in a specific scope, and the scope automatically manages their lifecycle: parent waits for children; cancellation propagates child-to-parent; no leaked coroutines.
  • ❓ Why is structured concurrency important?
    Prevents memory leaks, ensures cancellation works predictably, makes asynchronous code easier to reason about, avoids orphan coroutines.
  • ❓ What is a parent-child coroutine relationship?
    When a coroutine launches another coroutine inside its scope, the new coroutine becomes child. Parent job is responsible for completion and cancellation. Child failure normally cancels parent.
  • ❓ What is supervisorScope?
    A scope where child failures do NOT affect other children or the parent. Used when tasks are independent (e.g., UI updates + network calls).

🚀 Advanced Concepts

  • ❓ What are cold vs hot streams?
    Cold streams (Flow) produce values on demand per collector. Hot streams (SharedFlow, StateFlow) emit values independently of collectors; they are active even without subscribers.
  • ❓ Difference between Flow and Sequence?
    Sequence is blocking and uses CPU thread, no suspension. Flow is asynchronous, supports coroutines, backpressure, and cancellation. Flow can suspend on each emission.
  • ❓ What is withContext?
    Suspend function to switch dispatcher without creating a new coroutine. It suspends the current coroutine until block finishes, then returns result. Ideal for thread switching.
  • ❓ How do coroutines improve performance?
    Reduces thread blocking, lowers memory overhead, enables high concurrency with low resource usage, avoids expensive context switches.
  • ❓ How do coroutines work internally?
    Based on CPS (Continuation Passing Style). The compiler transforms suspend functions into state machines. Each suspension point is a state; continuations resume execution at next state.

📱 Android-Specific Coroutines

  • ❓ What is lifecycleScope?
    CoroutineScope tied to LifecycleOwner (Activity/Fragment). Cancelled when lifecycle destroys. Launches coroutines lifecycle-aware.
  • ❓ What is viewModelScope?
    CoroutineScope bound to ViewModel, cancelled automatically when ViewModel is cleared (onCleared()). Ideal for UI-related data operations.
  • ❓ Why should coroutines be lifecycle-aware?
    To avoid wasted resources, prevent crashes after destruction, stop unnecessary work when UI is not active, and ensure structured concurrency.
  • ❓ How do you avoid memory leaks with coroutines?
    Never use GlobalScope for long-lived operations tied to UI; always use lifecycle-aware scopes (viewModelScope, lifecycleScope) and cancel manual scopes properly.

❓ Common Interview Follow-ups

Q: Does withContext block the thread?
✔ No, it suspends the coroutine.
Q: When NOT to use withContext?
✔ When you need parallel execution → use async.
Q: Can we use withContext(Dispatchers.Main)?
✔ Yes, to return to the UI thread.

1️⃣ What is a Coroutine Dispatcher?
A dispatcher decides which thread or thread pool a coroutine runs on.
2️⃣ How many main dispatchers are there?
Four commonly used: Main, IO, Default, Unconfined (rare).
3️⃣ Difference between Dispatchers.IO and Dispatchers.Default?
IO → blocking work (network, DB) with large thread pool. Default → CPU-intensive (calculations, sorting) with limited threads (cores).
4️⃣ What happens if you run a network call on Dispatchers.Main?
UI freezes → ANR (Application Not Responding).
5️⃣ When should you use Dispatchers.Default?
For sorting, JSON parsing, encryption, heavy calculations.
6️⃣ What is Dispatchers.Unconfined?
Starts in current thread, resumes in any thread. 🚫 Avoid in production.
7️⃣ Can we change dispatcher inside a coroutine?
Yes, using withContext.
8️⃣ Does withContext create a new coroutine?
No. It suspends the current coroutine and switches the thread.
9️⃣ What dispatcher does viewModelScope.launch {} use by default?
Dispatchers.Main
🔟 What happens if you don’t specify a dispatcher?
Inherits parent’s dispatcher; otherwise Dispatchers.Default.

🔥 BONUS (Very Common)

Why is Dispatchers.IO not unlimited?
To avoid resource exhaustion; it expands up to a safe limit (max 64 threads by default) and reuses threads.

🔥 Tricky Coroutine Interview Scenarios (Senior Level)

1️⃣ UI Freeze Scenario
API call inside viewModelScope.launch {} without dispatcher → UI freezes.
Why? viewModelScope uses Dispatchers.Main by default. Network call on main thread → ANR.
✔ Fix: withContext(Dispatchers.IO) { apiCall() }
2️⃣ Parallel vs Sequential Confusion
val a = getA()
val b = getB()
Runs sequentially → not parallel.
✔ Fix: Use async for parallel work.
3️⃣ Coroutine Not Executing
launch { delay(1000); println("Hi") } inside main()
No CoroutineScope, JVM exits immediately.
✔ Fix: Use runBlocking or create scope.
4️⃣ Child Coroutine Crash
One child fails → all siblings cancel.
Default structured concurrency behavior.
✔ Fix: Use supervisorScope { }
5️⃣ Exception Not Caught
Exception inside launch not caught by try-catch.
launch is fire-and-forget.
✔ Fix: Use CoroutineExceptionHandler or async + await.
6️⃣ Memory Leak Scenario
Coroutine continues after Activity destroyed → used GlobalScope.
✔ Fix: Use lifecycleScope.launch { }.
7️⃣ Cancellation Not Working
Job cancelled but coroutine keeps running → No suspension points or blocking code.
✔ Fix: Use delay() or check isActive periodically.
8️⃣ Wrong Dispatcher Used
Heavy JSON parsing on Dispatchers.IO slows app.
CPU-heavy work → use Dispatchers.Default.
9️⃣ Flow Collection Bug
Flow collects multiple times after rotation → collector not lifecycle-aware.
✔ Fix: repeatOnLifecycle(Lifecycle.State.STARTED).
🔟 withContext Misuse
Developer uses launch(Dispatchers.IO) everywhere → unnecessary coroutines, breaks structured concurrency.
✔ Fix: Prefer withContext(Dispatchers.IO) for short thread-switching.

🔥 SUPER TRICKY BONUS

What happens here?
runBlocking {
  launch { delay(1000) }
  println("Done")
}
Answer: Prints "Done" after delay because runBlocking waits for all child coroutines to finish (structured concurrency).
