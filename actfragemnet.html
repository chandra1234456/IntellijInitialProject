📱 1. Application Class

1 What is the Application class in Android? When to use it?

Application class is the base class for maintaining global application state. It's instantiated before any other component. Use for: global initialization (Firebase, Crashlytics), dependency injection setup, global variables, and app-level callbacks.

class MyApplication : Application() {
    override fun onCreate() {
        super.onCreate()
        // Initialize SDKs, DI, etc.
        Firebase.initializeApp(this)
        AppCompatDelegate.setDefaultNightMode(AppCompatDelegate.MODE_NIGHT_FOLLOW_SYSTEM)
    }
}
2 How to declare custom Application in AndroidManifest?

Add the android:name attribute to the application tag in AndroidManifest.xml pointing to your custom Application class.

<application
    android:name=".MyApplication"
    android:icon="@mipmap/ic_launcher"
    android:label="@string/app_name">
    <activity android:name=".MainActivity">
    </activity>
</application>
3 What is the lifecycle of Application class?

Application has only one callback: onCreate(). It's created when the app process is created and exists until the process is killed. Register ActivityLifecycleCallbacks to monitor activity lifecycle globally.

4 Can there be multiple Application classes?

No, only one Application class per app process. However, for multi-process apps, each process gets its own Application instance.

🔄 2. Activity - Core UI Component

5 What is Activity in Android? Explain its lifecycle methods.

Activity is a UI component representing a single screen. Lifecycle: onCreate() → onStart() → onResume() → onPause() → onStop() → onDestroy(). Also onRestart() when returning from stopped state.

override fun onCreate(savedInstanceState: Bundle?) // Initialize UI
override fun onStart() // App becomes visible
override fun onResume() // App ready for user interaction
override fun onPause() // App losing focus
override fun onStop() // App no longer visible
override fun onDestroy() // Activity being destroyed
6 What is the difference between onPause() and onStop()?

onPause() called when activity partially visible (dialog overlay). onStop() called when activity completely hidden (new activity covers fully). onPause() should be lightweight (save data).

7 What is savedInstanceState? How to save and restore state?

savedInstanceState is a Bundle that saves UI state before activity destruction (rotation). Override onSaveInstanceState() and restore in onCreate() or onRestoreInstanceState().

override fun onSaveInstanceState(outState: Bundle) {
    super.onSaveInstanceState(outState)
    outState.putString("key", myData)
}

override fun onRestoreInstanceState(savedInstanceState: Bundle) {
    super.onRestoreInstanceState(savedInstanceState)
    myData = savedInstanceState.getString("key")
}
8 What are launch modes in Android? Explain each.

standard: New instance every time.
singleTop: Reuse if at top of stack.
singleTask: Single instance, clears activities above.
singleInstance: Single instance in its own task.

9 What is the difference between finish() and finishAffinity()?

finish() closes current activity. finishAffinity() finishes all activities in the current task and removes the task from the recent tasks list.

10 What is android:configChanges? When to use it?

android:configChanges prevents activity recreation on specific configuration changes (like orientation). Override onConfigurationChanged() to handle manually.

<activity android:name=".MainActivity"
    android:configChanges="orientation|screenSize|keyboardHidden" />

🧩 3. Fragment - Modular UI

11 What is Fragment? Explain fragment lifecycle.

Fragment is a reusable UI component within an Activity. Lifecycle: onAttach() → onCreate() → onCreateView() → onViewCreated() → onStart() → onResume() → onPause() → onStop() → onDestroyView() → onDestroy() → onDetach().

12 Difference between Fragment and Activity?
FeatureActivityFragment
IndependentYes, can exist aloneNo, depends on Activity
LifecycleIndependentTied to host Activity
ReusabilityLimitedHigh, can be reused
Back stackManaged by systemManaged by FragmentManager
13 What is FragmentManager and FragmentTransaction?

FragmentManager manages fragments in an Activity. FragmentTransaction performs operations (add, replace, remove, show, hide). Always commit transactions.

supportFragmentManager.commit {
    add(R.id.container, MyFragment())
    addToBackStack(null)
}
14 What is the difference between add() and replace() in FragmentTransaction?

add() adds fragment on top of existing ones. replace() removes existing fragments in container and adds new one. Use add() for navigation drawer, replace() for single-pane layouts.

15 What is the difference between commit() and commitAllowingStateLoss()?

commit() must be called before onSaveInstanceState() or throws exception. commitAllowingStateLoss() can be called after, but may lose fragment state. Use carefully.

16 How to communicate between fragments?

Use shared ViewModel (activity-scoped), interface callbacks, or FragmentResultListener (modern approach).

// Sending fragment
setFragmentResult("requestKey", bundleOf("key" to value))

// Receiving fragment
supportFragmentManager.setFragmentResultListener("requestKey") { key, bundle ->
    val value = bundle.getString("key")
}

⚙️ 4. Services - Background Processing

17 What is Service? Types of services in Android?

Service runs background operations without UI. Types: Started Service (runs until stopped), Bound Service (client-server), Foreground Service (user-visible notification).

18 Difference between Service and IntentService?

Service runs on main thread. IntentService (deprecated) ran on worker thread, stopped automatically. Modern replacement: WorkManager or CoroutineService with foreground handling.

19 What is Foreground Service? When to use?

Foreground Service shows persistent notification and is less likely to be killed. Used for music playback, location tracking, file downloads. Requires FOREGROUND_SERVICE permission.

startForeground(NOTIFICATION_ID, notification)
20 What are the limitations of Background Services in Android 8+ (Oreo)?

Android 8+ restricts background services: can't start background service while app is in background. Use WorkManager for deferred tasks, Foreground Service for immediate tasks, or JobScheduler.

21 What is WorkManager? When to use instead of Service?

WorkManager is recommended for deferrable background work that must execute reliably (API 14+). Handles constraints (network, battery). Use for periodic sync, data upload, log processing.

val workRequest = OneTimeWorkRequestBuilder<MyWorker>()
    .setConstraints(Constraints.Builder().setRequiredNetworkType(NetworkType.CONNECTED).build())
    .build()
WorkManager.getInstance(context).enqueue(workRequest)

📨 5. Intents - Messaging Component

22 What is Intent? Types of Intents?

Intent is a messaging object to request action from another component. Explicit Intent: specify component class. Implicit Intent: declare action, system resolves component.

// Explicit
Intent(this, TargetActivity::class.java)

// Implicit
Intent(Intent.ACTION_VIEW, Uri.parse("https://google.com"))
23 What is PendingIntent? When to use?

PendingIntent is a token granting permission to another app to execute an Intent. Used for notifications, alarms, AppWidgets, and Bluetooth.

val pendingIntent = PendingIntent.getActivity(
    context, 0, intent,
    PendingIntent.FLAG_UPDATE_CURRENT or PendingIntent.FLAG_IMMUTABLE
)
24 How to pass data between activities using Intent?

Use putExtra() with key-value pairs, or Bundle. Retrieve with getStringExtra(), getIntExtra(), etc.

// Sending
Intent(this, DetailActivity::class.java).apply {
    putExtra("user_id", 123)
    putExtra("user_name", "John")
    startActivity(this)
}

// Receiving
val userId = intent.getIntExtra("user_id", 0)
25 What is startActivityForResult() and its modern alternative?

startActivityForResult() (deprecated) returned results from another activity. Modern alternative: Activity Result API using registerForActivityResult().

private val getContent = registerForActivityResult(ActivityResultContracts.GetContent()) { uri: Uri? ->
    // Handle returned content
}

getContent.launch("image/*")

🗄️ 6. ContentProvider - Data Sharing

26 What is ContentProvider? When to use?

ContentProvider manages access to structured data, enabling data sharing across apps. Used for Contacts, MediaStore, Calendar, or custom app data sharing.

27 What is ContentResolver? How to query data?

ContentResolver interacts with ContentProvider. Use with URIs to query, insert, update, delete data.

val cursor = contentResolver.query(
    ContactsContract.Contacts.CONTENT_URI,
    null, null, null, null
)
28 What are ContentObservers? When to use?

ContentObserver listens for changes to ContentProvider data. Use to react to contacts changes, media changes, or sync data.

29 What are URI matchers? Why needed in custom ContentProvider?

UriMatcher helps match incoming URIs to specific operations (query by ID vs all items). Improves code organization and performance.

private val uriMatcher = UriMatcher(UriMatcher.NO_MATCH).apply {
    addURI(AUTHORITY, "items", ITEMS)
    addURI(AUTHORITY, "items/#", ITEM_ID)
}

🔧 7. Other Important Components

30 What is BroadcastReceiver? Types?

BroadcastReceiver listens for system or app broadcasts. Manifest-declared (static) - works even when app not running (restricted). Context-registered (dynamic) - works while app running.

// Register dynamically
val receiver = MyBroadcastReceiver()
registerReceiver(receiver, IntentFilter(Intent.ACTION_BATTERY_LOW))
31 What restrictions apply to BroadcastReceivers in Android 8+?

Manifest-declared receivers for implicit broadcasts are restricted (exceptions: BOOT_COMPLETED, some system events). Use WorkManager or JobScheduler instead.

32 What is JobScheduler? When to use?

JobScheduler schedules background jobs with constraints (network, charging, idle). Android 5.0+. For backward compatibility, use WorkManager.

33 What is AlarmManager? When to use?

AlarmManager schedules exact or inexact alarms at specific times. Use for precise timing (reminders, alarms). For non-critical tasks, use WorkManager.

34 What are App Components vs Process vs Thread?

App Components (Activity, Service, etc.) run in main thread by default. Process is an isolated execution environment. Thread is lightweight execution unit. Use background threads for long operations.

🎬 8. Scenario-Based Questions

S1 User receives a phone call while app is open. What happens to Activity lifecycle?

Activity goes: onPause() → onStop(). When call ends: onRestart() → onStart() → onResume(). Save critical data in onPause().

S2 How to play music in background when app is closed?

Use Foreground Service with notification. Start service from Activity, call startForeground(). Service continues even when Activity destroyed.

S3 User rotates screen while a dialog is showing. What happens?

Activity recreates, Dialog is dismissed. Use DialogFragment instead of Dialog - it survives rotation. ViewModel can also retain dialog state.

S4 How to share data between two completely different apps?

Use ContentProvider (structured data), share files via FileProvider, share text/images via Intent (ACTION_SEND), or use SharedPreferences with MODE_WORLD_READABLE (deprecated).

📊 9. Important Comparisons

C1 Activity vs Fragment vs View (when to use which?)

Activity: Standalone screen, entry point.
Fragment: Reusable UI portion, tablet layouts, ViewPager.
View: Individual UI elements, custom components.

C2 Service vs Thread vs AsyncTask (deprecated) vs Coroutines

Service: Background processing with lifecycle (system-managed).
Thread: Pure Java thread, no Android lifecycle.
Coroutines: Modern concurrency, lifecycle-aware (viewModelScope).
AsyncTask: Deprecated, use Coroutines/WorkManager.

C3 Implicit vs Explicit Intent - Real examples

Explicit: Opening your own activity: Intent(this, MyActivity::class.java)
Implicit: Opening browser, making call, picking photo.
