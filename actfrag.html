📱 Android Interview Questions (Advanced Edition)

🧠 Activity Lifecycle & Core Concepts

Q1. What are Activity lifecycle methods? Basic

onCreate → onStart → onResume → onPause → onStop → onDestroy

Q2. When is onPause() called? Basic

When activity is partially visible or another activity comes in front (e.g., a dialog or transparent activity).

Q3. Difference between onStop() and onDestroy()? Basic

onStop → activity not visible (still in memory).
onDestroy → activity is finishing or destroyed by system (cleanup happens here).

Q4. What is onSaveInstanceState()? Intermediate

Used to save temporary UI state before destruction (e.g., rotation). Data is restored in onCreate() or onRestoreInstanceState().

Q5. 🔥 What happens if an Activity is in background and system needs memory? Advanced

The system may kill the process. onSaveInstanceState() is called before it's killed. Then onRestoreInstanceState() or onCreate(Bundle) is called when user returns.

Q6. 🔥 Difference between onRestart() and onResume()? Intermediate

onRestart() is called when activity comes from stopped state (after onStop). onResume() is always called when activity becomes interactive — from either start or restart.

Q7. 🔥 What is the order when Activity A starts Activity B? Advanced

A: onPause → B: onCreate → onStart → onResume → A: onStop (if A no longer visible).

Q8. 🔥 Can you call finish() in onCreate()? What happens? Advanced

Yes. It will destroy the activity immediately. onDestroy() is called directly after onCreate() without going through onStart/onResume.

Q9. 🔥 What is android:configChanges and why use it? Advanced

It prevents activity recreation on specific configuration changes (like orientation). Use with caution — can cause view hierarchy issues if not handling changes manually.

🧩 Fragment Lifecycle & Advanced Concepts

Q1. Fragment lifecycle flow? Basic

onAttach → onCreate → onCreateView → onViewCreated → onStart → onResume → onPause → onStop → onDestroyView → onDestroy → onDetach

Q2. Difference between Activity & Fragment lifecycle? Basic

Fragment has additional view lifecycle methods (onCreateView, onDestroyView) and is attached to an activity (onAttach/onDetach).

Q3. onCreateView vs onViewCreated? Intermediate

onCreateView → inflate layout and return the root View.
onViewCreated → called after view is created; ideal for UI initialization, button clicks, adapters.

Q4. Why use Fragment? Basic

  • Reusable UI components across activities
  • Better modularity and easier for tablet/phone adaptation
  • Lifecycle management is more flexible

Q5. 🔥 What is the difference between replace() and add() when using fragments? Advanced

replace() removes existing fragment and adds new one (calls onDestroyView/onCreateView).
add() adds another fragment on top without destroying previous (useful for back stack management).

Q6. 🔥 How to pass data from Fragment to Activity? Intermediate

  • Interface callback (recommended)
  • Shared ViewModel (modern approach)
  • Using Fragment's arguments for Activity → Fragment communication

Q7. 🔥 What is FragmentManager and what does it do? Intermediate

Manages fragments in an activity: adding, removing, replacing, back stack operations, and finding fragments by ID or tag.

Q8. 🔥 What is the difference between commit() and commitNow()? Advanced

commit() schedules transaction asynchronously on main thread. commitNow() executes immediately synchronously (only for non-backstack transactions).

Q9. 🔥 Can a Fragment outlive its parent Activity? How? Advanced

Yes, with retainInstance = true (deprecated) or using ViewModel scoped to the activity. Also fragments added without UI (headless fragments) can survive config changes.

Q10. 🔥 What is ViewPager2 with Fragments? When is onResume called for each fragment? Advanced

ViewPager2 uses FragmentStateAdapter. By default, it creates offscreen pages (default limit = 1). onResume is called only when fragment becomes visible to user, not just when created.

🔗 Intents

Q1. What is an Intent?

Messaging object used to communicate between components.

Q2. Types of Intent?

  • Explicit → target component specified
  • Implicit → system decides component

Q3. Example of Explicit Intent

Intent(this, SecondActivity::class.java)

Q4. Example of Implicit Intent

Intent(Intent.ACTION_VIEW, Uri.parse("https://google.com"))

Q5. What is Intent Filter?

Defines which intents an app can respond to.

🔄 Tasks & Back Stack

Q1. What is Back Stack?

A stack of activities managed by Android. Pressing back button pops the top.

Q2. What happens when back button is pressed?

Current activity is popped and previous is resumed. If stack is empty, user goes to launcher.

Q3. What is launchMode?

  • standard
  • singleTop
  • singleTask
  • singleInstance

Q4. 🔥 What is the difference between singleTask and singleInstance? Advanced

singleTask allows other activities from other apps to be in the same task; singleInstance creates a new task with only that one activity — no other activities allowed.

Q5. What is taskAffinity?

Defines which task an activity belongs to. Used with singleTask or singleInstance to separate tasks.

Q6. 🔥 How to clear back stack programmatically? Intermediate

Use Intent.FLAG_ACTIVITY_CLEAR_TOP or FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_CLEAR_TASK, or call finishAffinity() on API 16+.

🌍 Context

Q1. What is Context?

Provides access to application resources and system services.

Q2. Types of Context?

  • Application Context
  • Activity Context
  • BaseContext (rarely used)

Q3. Difference between Application & Activity Context?

Application → global, long-lived, tied to app lifecycle.
Activity → tied to UI lifecycle, can show dialogs/themes.

Q4. When to use Application Context?

  • Singletons
  • Database instances
  • Retrofit / Dagger / Koin (avoid memory leaks)

Q5. Memory leak example?

Holding Activity context in static variable or long-running background task holding reference to Activity.

Q6. 🔥 Can you start an Activity from Application Context? Why? Advanced

No. You need FLAG_ACTIVITY_NEW_TASK to start from non-activity context. However, this may not behave as expected. Use Activity Context for starting activities.

⚡ Bonus: Activity & Fragment in Real Apps

🔥 What is the difference between getActivity() and requireActivity() in Fragment?

getActivity() can return null if fragment not attached; requireActivity() throws exception if null — safer for post-attach code.

🔥 When is onActivityResult called in Fragment? (Legacy)

When an activity started with startActivityForResult from fragment returns — fragment's onActivityResult receives result before activity's.

🔥 Explain the new Activity Result API (registerForActivityResult) vs deprecated onActivityResult.

New API is type-safe, uses contracts, decouples result handling, and works across fragments/activities without runtime checks.

🔥 How does setRetainInstance(true) work? (Deprecated but good to know)

It retained fragment instance across configuration changes, but now replaced by ViewModels.

🔥 What is android:parentActivityName and how does it affect back stack?

Defines logical parent activity for Up navigation (action bar back). When set, system can navigate up the hierarchy properly.
