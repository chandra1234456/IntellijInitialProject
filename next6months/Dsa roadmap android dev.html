01 Complexity, Arrays & Strings

The month where you stop guessing whether your code is O(n) or O(n²) — and Android code is full of both.

  • Big-O, time vs. space trade-offs
  • Arrays: two pointers, sliding window, prefix sums
  • Strings: pattern matching, anagrams, palindromes
  • Basic recursion — factorial, Fibonacci, backtracking intro
  • Math: GCD/LCM, primes, bit manipulation basics

02 Linked Lists, Stacks & Queues

Linear structures — the ones closest to what you already touch in Kotlin collections and coroutine channels.

  • Singly / doubly linked lists, fast-slow pointers
  • Stack: valid parentheses, monotonic stack
  • Queue & deque, circular queue
  • Implementing an LRU cache from scratch
  • Sorting: merge sort, quick sort, when each wins

03 Trees, BSTs & Recursion Depth

This is where Compose's UI tree, the View hierarchy, and JSON parsing all turn out to be the same shape.

  • Binary trees: traversals (in/pre/post/level order)
  • Binary Search Trees: insert, delete, validate
  • Height, diameter, LCA, balanced tree checks
  • Backtracking: subsets, permutations, N-Queens
  • Heaps & priority queues — intro

04 Graphs, Tries & Heaps

Denser structures — where most people's momentum drops. Budget slightly more time here than the other months.

  • Graph representations, BFS & DFS
  • Topological sort, cycle detection
  • Shortest paths: Dijkstra, Bellman-Ford (conceptual depth over memorizing)
  • Union-Find / Disjoint Set
  • Tries — prefix search, autocomplete
  • Heaps: k-way merge, top-k problems

05 Dynamic Programming & Greedy

The month people fear most, mostly because they skip straight to hard problems. Don't — build the pattern recognition slowly.

  • 1D DP: climbing stairs, house robber, coin change
  • 2D DP: knapsack, LCS, edit distance, grid paths
  • DP on subsequences and partitions
  • Greedy: interval scheduling, activity selection
  • Recognizing "is this DP or greedy?" in an interview

06 Revision, Mock Interviews & Android-Flavored DSA

No new topics. This month is entirely about speed, retention, and talking through your solutions out loud.

  • Re-solve every "starred" problem from months 1–5 cold, no notes
  • Timed mock interviews, 2–3 per week
  • Android-specific DSA questions: RecyclerView view recycling, image loading cache eviction, offline-sync conflict resolution
  • Explaining trade-offs out loud, not just producing working code
  • Light system design — since Android interviews often blend the two

A weekday you can actually repeat

20 min
Watch or read the concept for the day — don't skip this even when you're eager to jump into code.
40–60 min
Solve 1–2 problems on that concept. Struggle for real before checking a solution.
10 min
Write a two-line note on the pattern you used — this is what makes month 6 revision fast instead of painful.

Skip a day — skip one, not the week. The plan bends; it doesn't break from a missed Tuesday.
