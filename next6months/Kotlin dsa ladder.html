SCRATCH → PROBLEM SOLVER · FOR A 3.8 YOE ANDROID/KOTLIN DEV

You already ship apps. This rebuilds the muscle underneath that.

Shipping Android features and cold-solving a coding problem use different muscles — Android leans on frameworks doing the heavy lifting, interviews want you to build the logic yourself. This ladder rebuilds that muscle from plain Kotlin syntax up to real interview-level DSA, one rung at a time.

This is common, not a red flag. Plenty of experienced Android developers can architect a whole app but freeze on "reverse a string without a library function" — because day-to-day work rarely asks you to write raw logic. The fix isn't intelligence, it's reps on the specific muscle. Start at Rung 1 even if it feels too easy; that's the point.
1Get fluent in plain Kotlin — no algorithms yet

Before problem-solving, your fingers need to type Kotlin without hesitating — loops, conditionals, functions, collections — the way you'd type XML or Compose without thinking.

  • Variables, val vs var, basic types
  • if/else, when, for, while — write each 10 times until boring
  • Functions: parameters, return types, default args
  • Lists, Maps, Sets and their common operations
  • Null safety — ?., ?:, !! and why you rarely need the last one

2Basic programs — the classic warm-up set

Every language-learner's rite of passage. These feel trivial once you've done them, but skipping them is exactly why raw logic feels shaky later.

  • Swap two numbers (with and without a third variable)
  • Factorial, Fibonacci (loop, then recursive)
  • Check prime, check Armstrong number
  • Reverse a string / number without built-in reverse()
  • Check palindrome (string and number)
  • Print number/star patterns (triangle, pyramid, diamond)
  • Count vowels, count digits, sum of digits

3Arrays & strings — where "basic" turns into "DSA"

This is the bridge rung. Same comfort level as Rung 2, but now you're touching the actual building blocks — arrays and strings — that every DSA topic sits on top of.

  • Find max/min in an array without max()/min()
  • Find the second largest element
  • Remove duplicates from an array
  • Count frequency of each element (build your own HashMap logic)
  • Rotate an array by k positions
  • Check if two strings are anagrams
  • Merge two sorted arrays manually

5"Little medium" — the confidence-building step most people skip

The jump from Easy straight to Medium is where most people bounce off and feel like they've hit a wall. This rung exists to soften that — mediums that lean easy, and easy problems with a twist.

  • Group Anagrams, Top K Frequent Elements
  • Product of Array Except Self
  • Longest Substring Without Repeating Characters
  • 3Sum, Container With Most Water
  • Number of Islands (your first real graph problem)

6Medium DSA — where real interviews live

This is the actual bar for most product-company interviews. By now brute-force should be automatic — the real skill being tested here is optimizing it.

  • Trees: level order, validate BST, LCA
  • Backtracking: subsets, permutations, combination sum
  • Graphs: course schedule, clone graph
  • DP: coin change, longest increasing subsequence, house robber
  • Heaps: k closest points, top-k problems

7Mock interviews & company-focused revision

The last rung isn't about learning anything new — it's about proving the previous six under real interview conditions: a stranger watching, a timer running, a whiteboard or shared doc instead of an IDE with autocomplete.

  • Re-solve your "starred" problems from every rung above, cold
  • 2–3 timed mock interviews a week
  • Practice narrating your approach before writing any code
  • Target company-tagged question lists for your specific applications

A daily habit that survives a busy Android sprint

Consistency beats intensity here — one solved problem a day for six months outperforms a weekend binge every time.

15 min
Read the day's problem, attempt it fully before looking anything up — even if you get stuck.
15 min
Watch or read the solution only after a real attempt — compare it to what you wrote, not instead of writing.
5 min
Write a one-line note on the pattern you used — this is what makes Rung 7 revision fast instead of starting over.

If a rung ever feels genuinely too easy, that's the signal to move faster, not a sign you wasted time on it — the goal was never to feel challenged at every step, just to never feel lost.
