🗄️ 1. Room Database - Local Persistence

1 What is Room? Why use it over SQLite?

Room is an ORM (Object Relational Mapping) library that provides abstraction over SQLite. Benefits: compile-time SQL verification, less boilerplate, LiveData/Flow integration, migration support, and coroutines compatibility.

@Database(entities = [User::class], version = 1)
abstract class AppDatabase : RoomDatabase() {
    abstract fun userDao(): UserDao
}
2 What are the main components of Room?

Entity: Represents a table. DAO (Data Access Object): Defines database operations. Database: Main access point, holds database holder.

@Entity(tableName = "users")
data class User(
    @PrimaryKey val id: Int,
    @ColumnInfo(name = "user_name") val name: String,
    @Ignore val tempField: String = ""  // Not stored
)

@Dao
interface UserDao {
    @Insert suspend fun insert(user: User)
    @Update suspend fun update(user: User)
    @Delete suspend fun delete(user: User)
    @Query("SELECT * FROM users WHERE id = :id")
    suspend fun getUser(id: Int): User?
    @Query("SELECT * FROM users")
    fun getAllUsers(): Flow>
}
3 What are the different types of relationships in Room?

Room supports: @Embedded (nested objects), @Relation (one-to-one, one-to-many, many-to-many). For many-to-many, use junction table.

// One-to-Many
@Entity data class User(@PrimaryKey val userId: Int, val name: String)
@Entity data class Pet(@PrimaryKey val petId: Int, val ownerId: Int, val name: String)

data class UserWithPets(
    @Embedded val user: User,
    @Relation(parentColumn = "userId", entityColumn = "ownerId")
    val pets: List
)
4 How to handle database migrations in Room?

Use Migration class with addMigrations() in Room.databaseBuilder(). For complex migrations, use .fallbackToDestructiveMigration() as last resort.

val migration_1_2 = object : Migration(1, 2) {
    override fun migrate(database: SupportSQLiteDatabase) {
        database.execSQL("ALTER TABLE users ADD COLUMN age INTEGER DEFAULT 0 NOT NULL")
    }
}

Room.databaseBuilder(context, AppDatabase::class.java, "db-name")
    .addMigrations(migration_1_2)
    .build()
5 What is TypeConverter in Room?

TypeConverter converts custom data types to types Room can store (primitive types). Use @TypeConverter annotation.

class Converters {
    @TypeConverter
    fun fromTimestamp(value: Long?): Date? = value?.let { Date(it) }

    @TypeConverter
    fun dateToTimestamp(date: Date?): Long? = date?.time

    @TypeConverter
    fun fromStringList(value: String): List = value.split(",")

    @TypeConverter
    fun fromListString(list: List): String = list.joinToString(",")
}

@Database(entities = [User::class], version = 1)
@TypeConverters(Converters::class)
abstract class AppDatabase : RoomDatabase()

🧭 2. Navigation Component

6 What is Navigation Component? What problems does it solve?

Navigation Component manages fragment/activity navigation, handles back stack, provides type-safe argument passing, and visual navigation graphs. Solves manual fragment transaction complexity, back stack management, and deep linking.

7 What are the main parts of Navigation Component?

Navigation Graph (XML): Visual representation of destinations. NavHost: Container for destinations. NavController: Manages navigation actions.

<!-- nav_graph.xml -->
<navigation xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto"
    android:id="@+id/nav_graph"
    app:startDestination="@id/homeFragment">

    <fragment android:id="@+id/homeFragment" ... >
        <action android:id="@+id/action_to_detail"
            app:destination="@id/detailFragment" />
    </fragment>
</navigation>
8 How to pass data between destinations safely?

Use Safe Args plugin for type-safe argument passing. Generate directions and argument classes.

// Define argument in navigation graph
<argument android:name="userId" app:argType="integer" />

// Sending
val action = HomeFragmentDirections.actionToDetail(userId = 42)
findNavController().navigate(action)

// Receiving in destination
val userId = arguments?.getInt("userId") ?: 0
9 What are NavDeepLinkBuilder and deep linking?

Deep linking allows navigating directly to a destination via URI or intent. NavDeepLinkBuilder creates PendingIntent for notifications.

<deepLink app:uri="android-app://myapp.com/profile/{userId}" />

// Create deep link for notification
val pendingIntent = NavDeepLinkBuilder(context)
    .setGraph(R.navigation.nav_graph)
    .setDestination(R.id.profileFragment)
    .setArguments(bundleOf("userId" to 123))
    .createPendingIntent()
10 What is NavigationUI? How to set up with AppBarConfiguration?

NavigationUI provides helper methods to connect NavController with AppBarLayout, BottomNavigationView, and NavigationView.

val navController = findNavController(R.id.nav_host_fragment)
val appBarConfiguration = AppBarConfiguration(
    setOf(R.id.home, R.id.profile, R.id.settings),
    drawerLayout
)
setupActionBarWithNavController(navController, appBarConfiguration)
NavigationUI.setupWithNavController(bottomNavView, navController)

⚙️ 3. WorkManager - Background Processing

11 What is WorkManager? When to use it?

WorkManager is Android's recommended solution for deferrable, guaranteed background work that must execute even after app restart or device reboot. Use for: periodic sync, data upload, log processing, image compression.

12 Types of Workers in WorkManager?

Worker: Runs on background thread (uses Dispatchers.IO). CoroutineWorker: For coroutines, suspend functions. ListenableWorker: Lowest level, manual threading.

class UploadWorker(context: Context, params: WorkerParameters) : CoroutineWorker(context, params) {
    override suspend fun doWork(): Result = try {
        // Do background work
        uploadData()
        Result.success()
    } catch (e: Exception) {
        Result.retry()
    }
}
13 How to chain WorkRequests and handle constraints?
val constraints = Constraints.Builder()
    .setRequiredNetworkType(NetworkType.CONNECTED)
    .setRequiresBatteryNotLow(true)
    .setRequiresCharging(false)
    .build()

val uploadWork = OneTimeWorkRequestBuilder()
    .setConstraints(constraints)
    .setBackoffCriteria(BackoffPolicy.EXPONENTIAL, 30, TimeUnit.SECONDS)
    .addTag("upload_tag")
    .build()

// Chaining
WorkManager.getInstance(context)
    .beginWith(downloadWork)
    .then(processWork)
    .then(uploadWork)
    .enqueue()

// Unique work
WorkManager.getInstance(context)
    .enqueueUniqueWork("unique_upload", ExistingWorkPolicy.KEEP, uploadWork)
14 How to get work results and observe progress?
// Observe work status
WorkManager.getInstance(context).getWorkInfoByIdLiveData(workRequest.id)
    .observe(lifecycleOwner) { info ->
        when(info.state) {
            WorkInfo.State.SUCCEEDED -> // Handle success
            WorkInfo.State.FAILED -> // Handle failure
            WorkInfo.State.RUNNING -> // Get progress
        }
    }

// Report progress in CoroutineWorker
setProgress(workDataOf("progress" to 50))
Result.success(workDataOf("result_key" to "success"))
15 PeriodicWorkRequest and its limitations?

PeriodicWorkRequest for recurring tasks. Minimum interval is 15 minutes. Cannot have initial delay less than 15 minutes. Use setFlexInterval() for flexible execution window.

val periodicWork = PeriodicWorkRequestBuilder(1, TimeUnit.HOURS)
    .setFlexPeriod(15, TimeUnit.MINUTES)
    .build()

💾 4. DataStore - Modern Data Storage

16 What is DataStore? Types and benefits over SharedPreferences?

DataStore is modern, coroutine-based data storage. Types: Preferences DataStore (key-value, like SharedPreferences), Proto DataStore (typed objects with schema). Benefits: asynchronous, type-safe (Proto), coroutine support, no blocking main thread.

17 How to implement Preferences DataStore?
// Create DataStore
val Context.dataStore by preferencesDataStore(name = "user_preferences")

// Define keys
val USER_NAME = stringPreferencesKey("user_name")
val USER_AGE = intPreferencesKey("user_age")

// Write data (suspend)
suspend fun saveUserName(name: String) {
    context.dataStore.edit { preferences ->
        preferences[USER_NAME] = name
    }
}

// Read data (Flow)
val userNameFlow: Flow = context.dataStore.data
    .map { preferences ->
        preferences[USER_NAME] ?: ""
    }
18 What is Proto DataStore? How to implement?

Proto DataStore uses Protocol Buffers for type-safety. Define schema in .proto file, then generated code.

// user_preferences.proto
syntax = "proto3";
message UserPreferences {
    string name = 1;
    int32 age = 2;
    bool notifications_enabled = 3;
}

// Create serializer
object UserPreferencesSerializer : Serializer {
    override val defaultValue: UserPreferences = UserPreferences.getDefaultInstance()
    override suspend fun readFrom(input: InputStream): UserPreferences {
        return UserPreferences.parseFrom(input)
    }
    override suspend fun writeTo(t: UserPreferences, output: OutputStream) {
        t.writeTo(output)
    }
}

// Create DataStore
val Context.userPreferencesStore by dataStore(
    fileName = "user_prefs.pb",
    serializer = UserPreferencesSerializer
)
19 How to handle migration from SharedPreferences to DataStore?
val Context.dataStore by preferencesDataStore(
    name = "new_preferences",
    produceMigrations = { context ->
        listOf(SharedPreferencesMigration(context, "old_shared_prefs"))
    }
)

📄 5. Paging 3 Library

20 What is Paging 3? Problems it solves?

Paging 3 loads data incrementally, improves performance, reduces memory usage. Features: built-in error handling, placeholder support, different data sources (network, database, combined), integration with RecyclerView.

21 What are the main components of Paging 3?

PagingSource: Defines how to load data. Pager: Builds Flow. PagingDataAdapter: RecyclerView adapter. RemoteMediator: For network-database sync.

class UserPagingSource : PagingSource() {
    override suspend fun load(params: LoadParams): LoadResult {
        return try {
            val page = params.key ?: 1
            val response = api.getUsers(page, params.loadSize)
            LoadResult.Page(
                data = response.users,
                prevKey = if (page > 1) page - 1 else null,
                nextKey = if (response.hasNext) page + 1 else null
            )
        } catch (e: Exception) {
            LoadResult.Error(e)
        }
    }
}
22 How to set up Pager and PagingDataAdapter?
// In ViewModel
val pagingDataFlow = Pager(PagingConfig(pageSize = 20, enablePlaceholders = true)) {
    UserPagingSource()
}.flow.cachedIn(viewModelScope)

// In Fragment/Activity
val adapter = UserAdapter()
recyclerView.adapter = adapter

lifecycleScope.launch {
    repeatOnLifecycle(Lifecycle.State.STARTED) {
        viewModel.pagingDataFlow.collect { pagingData ->
            adapter.submitData(pagingData)
        }
    }
}

RemoteMediator handles network-database synchronization for Paging 3. Use when you need offline support: load from network, save to Room, then display from database.

🎬 6. Scenario-Based Questions

S1 Scenario: App needs offline-first support with large user list, pagination, and search.

Combine Room + Paging 3 + RemoteMediator: Use Room as single source of truth, RemoteMediator for network sync, Paging 3 for efficient loading. Implement search using @Query with LIKE operator and Flow for real-time updates.

S2 Scenario: Background task to sync data every 4 hours, only when device has internet and charging.

Use PeriodicWorkRequest with constraints: setRequiredNetworkType(CONNECTED), setRequiresCharging(true). Use unique work to prevent duplicate syncs.

S3 Scenario: User preferences need to be saved (theme, notifications) with coroutine support.

Use Preferences DataStore. Expose Flow for observing changes, suspend functions for writes. Use viewModelScope for coroutine operations.

S4 Scenario: Deep linking to specific product page from notification.

Use Navigation Component with deep link. Add in navigation graph, create PendingIntent with NavDeepLinkBuilder, handle arguments in destination fragment.

C4 DataStore with preferences and FlowMedium
class SettingsRepository(private val context: Context) {
    private val Context.dataStore by preferencesDataStore("settings")

    private val THEME_KEY = stringPreferencesKey("theme")
    private val NOTIFICATIONS_KEY = booleanPreferencesKey("notifications")

    val themeFlow: Flow = context.dataStore.data
        .map { preferences -> preferences[THEME_KEY] ?: "light" }

    val notificationsFlow: Flow = context.dataStore.data
        .map { preferences -> preferences[NOTIFICATIONS_KEY] ?: true }

    suspend fun setTheme(theme: String) {
        context.dataStore.edit { preferences ->
            preferences[THEME_KEY] = theme
        }
    }

    suspend fun setNotifications(enabled: Boolean) {
        context.dataStore.edit { preferences ->
            preferences[NOTIFICATIONS_KEY] = enabled
        }
    }
}
C5 Paging 3 with custom PagingSource and error handlingHard
class PostPagingSource(
    private val api: ApiService
) : PagingSource() {

    override suspend fun load(params: LoadParams): LoadResult {
        return try {
            val page = params.key ?: 1
            val response = api.getPosts(page, params.loadSize)

            LoadResult.Page(
                data = response.posts,
                prevKey = if (page > 1) page - 1 else null,
                nextKey = if (response.hasNextPage) page + 1 else null
            )
        } catch (e: IOException) {
            LoadResult.Error(e)
        } catch (e: HttpException) {
            LoadResult.Error(e)
        }
    }

    override fun getRefreshKey(state: PagingState): Int? {
        return state.anchorPosition?.let { anchorPosition ->
            state.closestPageToPosition(anchorPosition)?.prevKey?.plus(1)
                ?: state.closestPageToPosition(anchorPosition)?.nextKey?.minus(1)
        }
    }
}

// In ViewModel

    PostPagingSource(api)
}.flow.cachedIn(viewModelScope)

✨ 8. Best Practices & Interview Tips

🎯 Key Takeaways:
• Room: Always use suspend functions or Flow for DB operations, handle migrations properly
• Navigation: Use Safe Args, avoid manual fragment transactions, handle deep links
• WorkManager: Choose appropriate Worker type, set constraints wisely, handle retries
• DataStore: Prefer Proto for complex data, migrate from SharedPreferences properly
• Paging 3: Use RemoteMediator for offline support, handle loading states gracefully
• Always test these components: Room (in-memory DB), WorkManager (TestDriver), Navigation (NavController testing)
