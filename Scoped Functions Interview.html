let · run · with · apply · also — differences, use-cases, and real Android patterns

✅ Scoped functions are top favourite interview topics for Android developers. This guide covers every possible question — from basic differences to advanced chaining, null safety, and best practices.

🎯 1. Core Concepts – What & Why

❓ What are scoped functions in Kotlin?
Scoped functions (let, run, with, apply, also) execute a block of code within the context of an object. They provide a temporary scope, reduce repetition, and improve readability by leveraging lambda with receiver or lambda with argument.
❓ How many scoped functions exist in Kotlin standard library?
Five: let, run, with, apply, also. Each differs by context object reference (it vs this) and return value (context object vs lambda result).
❓ What is the difference between it and this in scope functions?
it is the implicit name of the single argument in lambdas (let, also). this is the receiver inside lambdas for run, with, apply. Use it when you want to rename or pass around, use this for calling methods/properties directly.

🧩 3. Deep-Dive Questions with Code Examples

🔹 Q: Explain let with safe call operator. Why is it popular in Android?
let executes block only when object is not null. Avoids explicit if-null checks. 
val name: String? = "Kotlin"
name?.let {
    println("Length = ${it.length}")  // runs only if non-null
}
✅ Perfect for nullable view binding, intent extras, or Firebase user.
🔹 Q: When to use apply vs run?
apply returns the same object → for configuration. run returns lambda result → for computing value after setup. 
// apply - initialize TextView
val textView = TextView(context).apply {
    text = "Hello"
    textSize = 16f
    setPadding(8,8,8,8)
}

// run - compute result after config
val length = StringBuilder().run {
    append("Hello")
    append(" World")
    toString().length
}
🔹 Q: Difference between also and let?
Both use it. also returns the original object (for side effects). let returns lambda result. 
// also: logging without breaking chain
val user = User("Alice").also {
    println("Created user: ${it.name}")
}

// let: transformation
val upperName = user?.let { it.name.uppercase() }
🔹 Q: What is the difference between with and run?
with is a top-level function that takes an object as argument, while run is an extension function. with is used when you already have an object and want to perform multiple operations, run works as scope + result. 
// with – grouping actions on a non-null object
val person = Person()
with(person) {
    name = "Alex"
    age = 30
}

// run – similar but called on object (more idiomatic)
person.run {
    name = "Alex"
    age = 30
}
🔹 Q: Can you nest scoped functions? Any downside?
Yes, but nesting reduces readability. Use judiciously. Example: 
person?.let {
    it.address?.let { addr ->
        println(addr.city)
    }
}
✔ Better: use multiple let chains or extract functions.

📱 4. Android-Specific Scoped Function Scenarios

📌 Q: How to safely access nullable ViewModel data in Fragment? 
viewModel.userData?.let { user ->
    userNameTextView.text = user.name
    emailTextView.text = user.email
}
Using let ensures block only runs if data is not null.
📌 Q: How to initialize an Intent with extras using apply? 
val intent = Intent(context, DetailActivity::class.java).apply {
    putExtra("id", userId)
    putExtra("title", title)
}
startActivity(intent)
✅ apply returns the Intent itself → builder pattern.
📌 Q: Android RecyclerView adapter – using also for item click logging? 
holder.itemView.setOnClickListener {
    val position = adapterPosition
    itemList.getOrNull(position)?.also { clickedItem ->
        Log.d("Click", "Item: ${clickedItem.name}")
        onItemClick(clickedItem)
    }
}
also performs side effect (logging) and returns the object for further use.
📌 Q: View binding with apply – why is it common? 
private val binding = ActivityMainBinding.inflate(layoutInflater).apply {
    buttonSubmit.setOnClickListener { handleClick() }
    textTitle.text = "Welcome"
}
setContentView(binding.root)
✔ Apply configures binding in one go, returns binding instance.

🎓 5. Advanced & Tricky Interview Questions

🔥 Q: What is the difference between run and let for null safety?
Both support safe calls (?.let and ?.run). let uses it — better when you need explicit naming. run uses this — better for calling object methods without prefix. 
// let with smart cast
val nullableStr: String? = "hello"
nullableStr?.let { println(it.length) }

// run also works but `this` inside lambda
nullableStr?.run { println(length) }
🧠 Q: Can also be used to mutate an object? Is it pure side effect?
Yes, but the convention is to use also for actions that don't alter the object's core state (logging, analytics, validation). For configuration, use apply. However, also can mutate — but that’s less idiomatic. 
val list = mutableListOf(1,2,3).also { it.add(4) } // works but not idiomatic
⚡ Q: Which scoped function would you use for a builder pattern returning the same object?
apply is the go-to builder function because it returns the receiver object after configuration. 
class Car {
    var color = ""
    var model = ""
    fun build() = this
}
val myCar = Car().apply {
    color = "Red"
    model = "Tesla"
}
📦 Q: Which function would you choose for a block that returns a completely different type?
let or run depending on context. Use let when you need to transform nullable result, use run when you operate on a non-null object to compute a separate result. 
val result = person?.let { "${it.name} ${it.age}" }
val fullName = person.run { "$name $lastName" }

📋 6. Quick Reference Cheatsheet (Memory Aid)

🎯 Decision tree:
• Need to execute only if NOT NULL? → ?.let { }
• Configure object and return object itself? → apply { }
• Perform side effects, keep object? → also { }
• Operate on object + compute result? → run { } or let { }
• Group calls on existing object (without chaining)? → with(obj) { }

📝 7. Common Mistake Questions (Interview Traps)

⚠️ Q: What happens if you use apply on a nullable type without safe call?
Compiler error: apply is an extension function on the receiver type. If object is nullable, you must use ?.apply for safe execution.
⚠️ Q: Is with an extension function?
No, with is a regular inline function that takes an object as first argument, not an extension. That’s why you can’t call it using ?.with.
⚠️ Q: Which scope function returns the lambda result and uses this as context?
run (extension) and with (non-extension) both return lambda result and use this inside block.

🏆 8. Performance & Inline – Interview Worthy

🔥 Q: Are scoped functions inline? Does it cause performance overhead?
All five scoped functions are inline functions. The compiler copies the lambda bytecode directly, so no extra object allocation. Zero performance penalty compared to writing blocks manually.
💡 Q: What is the difference between run and with regarding inline?
Both are inline, but run is an extension, with takes receiver as argument. However, for most cases prefer run for conciseness when you already have the object.

🧪 9. Scoped Function Chaining – Real Android Example

// Real-world usage in ViewModel / Fragment
fun loadUserProfile() {
    repository.getUser()
        ?.let { user ->
            user.name?.let { name ->
                updateUI(name)
            }
        }
        .also { Log.d("Debug", "Profile loaded attempt") }
}
🧩 let + also chain is extremely common: transformation + side effect.
✅ Q: When would you use apply instead of also for configuration?
apply is for direct member assignment (this context). also is for operations that refer to object via it (like logging, validation). Use apply when setting properties; use also when you need to pass object to another function or log it.
