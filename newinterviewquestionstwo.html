Advanced Android Interview Questions & Answers

Kotlin

1. What are Coroutines and why use them?
Coroutines are used for asynchronous programming in Kotlin. They allow writing non-blocking code in a sequential way. Key benefits: - Lightweight (compared to threads) - Structured concurrency - Easy error handling Example: 
viewModelScope.launch {
    val data = repository.getData()
    _state.value = data
}
2. What is Flow?
Flow is a cold asynchronous stream that emits multiple values over time. - Works well with Room & APIs - Supports operators like map, filter Example: 
repository.getUsers()
    .collect { users ->
        println(users)
    }

Jetpack Compose

3. What is recomposition?
Recomposition happens when state changes and Compose redraws only affected UI. Important points: - Efficient (only updates needed parts) - Triggered by State changes Example: 
var count by remember { mutableStateOf(0) }
Button(onClick = { count++ }) {
    Text("Count: $count")
}
4. What is State Hoisting?
State hoisting means moving state to a parent composable to make components reusable and testable. Pattern: - Stateless UI - State managed in ViewModel

MVVM + Clean Architecture

5. Explain MVVM with flow.
- View → observes state - ViewModel → holds UI logic - Repository → data source Flow: UI → ViewModel → UseCase → Repository → Data Example: 
class UserViewModel : ViewModel() {
    val users = repository.getUsers().stateIn(...)
}
6. Where should business logic go?
Business logic belongs in the Domain layer (UseCases), not in ViewModel. Why: - Better testability - Separation of concerns

Hilt / DI

7. How does Hilt work?
Hilt generates dependency graph at compile time. Steps: - Annotate Application with @HiltAndroidApp - Use @Inject for dependencies - Use @AndroidEntryPoint for Activities Example: 
@HiltAndroidApp
class MyApp : Application()
8. What are scopes?
Scopes define lifecycle of dependencies. Examples: - Singleton → entire app - ViewModelScoped → per ViewModel Wrong scoping can cause memory leaks.

Room

9. How does Room work internally?
Room generates code at compile time for: - DAO implementations - Query validation Example: 
@Dao
interface UserDao {
    @Query("SELECT * FROM users")
    fun getUsers(): Flow>
}

Testing

10. How do you test a ViewModel?
- Mock repository using Mockito - Use JUnit - Verify state output Example: 
@Test
fun testUsers() = runTest {
    whenever(repo.getUsers()).thenReturn(flowOf(listOf(User())))
    val vm = UserViewModel(repo)
    assert(vm.users.first().isNotEmpty())
}

BLE / IoT

11. BLE connection flow?
1. Scan devices 2. Connect 3. Discover services 4. Read/Write characteristics Challenges: - Connection drops - Battery usage - Permissions (Android 12+)
12. How to handle disconnections?
- Implement retry logic - Use callbacks - Maintain connection state Best practice: Use exponential backoff retry
