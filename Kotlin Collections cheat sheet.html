OVERVIEW & TYPES
The collection hierarchy
List IMMUTABLE

Ordered, allows duplicates. Access by index. Created with listOf().

Backed by Java's ArrayList internally. Read-only view.

MutableList MUTABLE

Ordered, allows duplicates. Can add/remove/modify. Created with mutableListOf() or ArrayList().

Map IMMUTABLE

Key-value pairs. Keys unique, values can duplicate. Created with mapOf().

Backed by Java LinkedHashMap — preserves insertion order.

MutableMap MUTABLE

Can add/update/remove entries. mutableMapOf(), hashMapOf(), linkedMapOf().

Set IMMUTABLE

No duplicates. No guaranteed order (unless LinkedHashSet). Created with setOf().

Sequence LAZY

Lazy evaluation — operations are computed only when terminal op is called. Use for large/infinite data. Created with sequenceOf() or .asSequence().

⚠ Interview trap: Kotlin's listOf() is read-only but NOT immutable — it's a view over a mutable Java list. Casting to MutableList can bypass read-only restriction. True immutability requires Collections.unmodifiableList() or ImmutableList from Guava.
CollectionTypes.kt 
// ── Immutable (read-only view) ─────────────────────────────
val list  = listOf(1, 2, 3)          // List<Int>
val map   = mapOf("a" to 1, "b" to 2) // Map<String, Int>
val set   = setOf(1, 2, 2, 3)       // Set<Int> → {1, 2, 3}
val empty = emptyList<String>()      // optimised singleton

// ── Mutable ────────────────────────────────────────────────
val mList = mutableListOf("a", "b") // ArrayList under the hood
val mMap  = mutableMapOf<String, Int>()
val mSet  = mutableSetOf(1, 2, 3)

// ── Specialised Maps ───────────────────────────────────────
val hash   = hashMapOf("k" to 1)    // O(1) lookup, no order
val linked = linkedMapOf("k" to 1)  // insertion order
val sorted = sortedMapOf("b" to 2, "a" to 1) // TreeMap, sorted by key

// ── buildList (Kotlin 1.6+) ────────────────────────────────
val built = buildList {
    add("first")
    addAll(listOf("second", "third"))
}  // returns immutable List<String>

MAP OPERATIONS
Key-value mastery
MapOps.kt 
val map = mapOf("a" to 1, "b" to 2, "c" to 3)

// ── Access ─────────────────────────────────────────────────
map["a"]                         // 1 (nullable)
map.getValue("a")                // 1 (throws if missing)
map.getOrDefault("z", 0)        // 0
map.getOrElse("z") { -1 }       // -1

// ── MutableMap operations ──────────────────────────────────
val m = mutableMapOf("a" to 1)
m.put("b", 2)                     // adds "b"
m.putIfAbsent("a", 99)            // no-op, "a" exists
m.getOrPut("c") { 3 }            // adds "c"=3, returns 3
m.merge("a", 10) { old, new -> old + new }  // a=11

// ── Transform ─────────────────────────────────────────────
map.mapValues { it.value * 2 }   // {a=2, b=4, c=6}
map.mapKeys { it.key.uppercase() } // {A=1, B=2, C=3}
map.filterValues { it > 1 }     // {b=2, c=3}
map.filterKeys { it != "a" }    // {b=2, c=3}

// ── Destructuring ─────────────────────────────────────────
for ((key, value) in map) {
    println("$key → $value")
}

// ── Convert to List of entries ─────────────────────────────
map.toList()                      // List<Pair<String,Int>>
map.entries.sortedBy { it.value } // sorted by value

// ── Frequency map (interview favourite!) ───────────────────
val words = listOf("a","b","a","c","b","a")
val freq = words.groupingBy { it }.eachCount()  // {a=3, b=2, c=1}
// alternative:
val freq2 = mutableMapOf<String, Int>()
words.forEach { freq2.merge(it, 1, Int::plus) }

SET OPERATIONS
Mathematical set algebra
SetOps.kt 
val a = setOf(1, 2, 3, 4)
val b = setOf(3, 4, 5, 6)

// Set algebra
a union b         // {1,2,3,4,5,6} — all elements
a intersect b     // {3,4}         — common elements
a subtract b      // {1,2}         — in a but not b
a + b              // same as union
a - b              // same as subtract

// Contains is O(1) for HashSet
a.contains(3)      // true, O(1)
listOf(1,2,3).contains(3) // true, O(n) — prefer Set for lookup!

// LinkedHashSet — preserves insertion order
val linked = linkedSetOf(3, 1, 2)  // {3, 1, 2}

// TreeSet — sorted
val sorted = sortedSetOf(3, 1, 2)  // {1, 2, 3}
✦ Android tip: Use Set for permission sets, unique IDs, or deduplicating API responses. list.toSet().toList() is a concise deduplicate — but order may change unless you use distinct().

Transform.kt 
data class User(val id: Int, val name: String, val active: Boolean)
val users = listOf(
    User(1, "Alice", true),
    User(2, "Bob",   false),
    User(3, "Carol", true)
)

// map — transform
users.map { it.name }              // [Alice, Bob, Carol]

// mapNotNull — transform + filter nulls
users.mapNotNull { if (it.active) it.name else null }  // [Alice, Carol]

// associateBy — List → Map by key
users.associateBy { it.id }        // {1=User(Alice), 2=User(Bob)...}

// associateWith — each element → computed value
users.associateWith { it.name.length }  // {User(Alice)=5, ...}

// associate — full control of key AND value
users.associate { it.id to it.name }  // {1=Alice, 2=Bob, 3=Carol}

// flatMap — users with multiple roles
data class Team(val name: String, val members: List<String>)
val teams = listOf(
    Team("Android", listOf("Alice", "Bob")),
    Team("iOS",     listOf("Carol"))
)
teams.flatMap { it.members }       // [Alice, Bob, Carol]

FILTER & SEARCH
filter · find · any · all · none · partition
FilterSearch.kt 
val nums = listOf(1, 2, 3, 4, 5, 6)

// ── Filter variants ────────────────────────────────────────
nums.filter { it % 2 == 0 }        // [2, 4, 6]
nums.filterNot { it % 2 == 0 }     // [1, 3, 5]
nums.filterIndexed { i, v -> i % 2 == 0 }  // [1, 3, 5] (even indices)
nums.filterIsInstance<Int>()        // type-safe filter

// ── Search ─────────────────────────────────────────────────
nums.find { it > 3 }               // 4 (first match, or null)
nums.findLast { it > 3 }           // 6
nums.indexOfFirst { it > 3 }       // 3
nums.binarySearch(4)               // works only on sorted list

// ── Boolean checks ─────────────────────────────────────────
nums.any { it > 5 }                // true — short-circuits
nums.all { it > 0 }                // true
nums.none { it < 0 }               // true
nums.count { it % 2 == 0 }        // 3

// ── Partition ─────────────────────────────────────────────
val (evens, odds) = nums.partition { it % 2 == 0 }
// evens=[2,4,6]  odds=[1,3,5]

// ── take / drop ────────────────────────────────────────────
nums.take(3)                        // [1, 2, 3]
nums.drop(3)                        // [4, 5, 6]
nums.takeWhile { it < 4 }          // [1, 2, 3]
nums.dropWhile { it < 4 }          // [4, 5, 6]
nums.takeLast(2)                   // [5, 6]

AGGREGATE
reduce · fold · sum · min · max
Aggregate.kt 
val nums = listOf(1, 2, 3, 4, 5)

// ── reduce — no initial value, uses first element ──────────
nums.reduce { acc, n -> acc + n }   // 15  (throws on empty!)
nums.reduceOrNull { acc, n -> acc + n }  // 15 or null

// ── fold — has initial value, safe on empty ────────────────
nums.fold(0) { acc, n -> acc + n } // 15
nums.fold(1) { acc, n -> acc * n } // 120 (factorial)

// ── foldIndexed ────────────────────────────────────────────
nums.foldIndexed("") { i, acc, v ->
    if (i == 0) "$v" else "$acc,$v"
}  // "1,2,3,4,5"

// ── runningFold — intermediate results ─────────────────────
nums.runningFold(0) { acc, n -> acc + n }
// [0, 1, 3, 6, 10, 15]  ← running sum prefix

// ── Sum/Min/Max helpers ────────────────────────────────────
nums.sum()                           // 15
nums.sumOf { it * 2 }              // 30
nums.average()                       // 3.0
nums.min()                           // 1
nums.max()                           // 5
nums.minOf { it * -1 }             // -5
nums.maxByOrNull { it % 3 }        // 2 (highest remainder)
⚠ Interview trap: reduce throws UnsupportedOperationException on an empty list. Always use reduceOrNull or fold in production code where the list might be empty.

GROUPING & SORTING
groupBy · sortedBy · compareBy
GroupSort.kt 
data class Product(val name: String, val category: String, val price: Double)
val products = listOf(
    Product("Phone",  "Electronics", 699.0),
    Product("Shirt",  "Clothing",     29.0),
    Product("Laptop", "Electronics", 1299.0),
    Product("Pants",  "Clothing",     49.0)
)

// ── groupBy → Map<K, List<T>> ─────────────────────────────
val byCategory = products.groupBy { it.category }
// {Electronics=[Phone, Laptop], Clothing=[Shirt, Pants]}

// ── groupBy with transform ─────────────────────────────────
products.groupBy({ it.category }, { it.name })
// {Electronics=[Phone, Laptop], Clothing=[Shirt, Pants]}

// ── Sorting ────────────────────────────────────────────────
products.sortedBy { it.price }           // ascending
products.sortedByDescending { it.price } // descending

// ── Multi-key sort ─────────────────────────────────────────
products.sortedWith(
    compareBy({ it.category }, { it.price })
)  // sort by category, then price within category

// ── min/max by property ────────────────────────────────────
products.minByOrNull { it.price }  // Shirt (29.0)
products.maxByOrNull { it.price }  // Laptop (1299.0)

// ── groupingBy + eachCount ─────────────────────────────────
products.groupingBy { it.category }.eachCount()
// {Electronics=2, Clothing=2}

// ── aggregate ─────────────────────────────────────────────
products.groupingBy { it.category }
    .aggregate { _, acc: Double?, el, _ -> (acc ?: 0.0) + el.price }
// {Electronics=1998.0, Clothing=78.0} — sum per category

SEQUENCE
Lazy evaluation · large datasets
ℹ When to use Sequence: Use .asSequence() when you chain 3+ operations on large lists (>1000 elements). Collections create intermediate lists at every step. Sequences process element-by-element lazily. Never use Sequence on small lists — the overhead outweighs the benefit.
Sequence.kt 
// ── Collection — creates 3 intermediate lists ──────────────
val result1 = (1..1_000_000)
    .filter { it % 2 == 0 }    // intermediate List 1
    .map { it * 3 }             // intermediate List 2
    .take(5)                    // intermediate List 3

// ── Sequence — processes element-by-element, no intermediates
val result2 = (1..1_000_000).asSequence()
    .filter { it % 2 == 0 }    // lazy, no list yet
    .map { it * 3 }             // lazy, no list yet
    .take(5)                    // lazy, no list yet
    .toList()                   // ← TERMINAL OP: now executes!

// ── generateSequence — infinite sequences ─────────────────
val naturals = generateSequence(1) { it + 1 }
naturals.take(5).toList()      // [1, 2, 3, 4, 5]

// Fibonacci sequence
val fibs = generateSequence(1 to 1) { it.second to it.first + it.second }
    .map { it.first }
fibs.take(8).toList()           // [1,1,2,3,5,8,13,21]

// ── sequence builder ───────────────────────────────────────
val custom = sequence {
    yield(1)
    yieldAll(listOf(2, 3))
    yield(4)
}
custom.toList()                  // [1, 2, 3, 4]

INTERVIEW Q & A
Click questions to reveal answers
Q What is the difference between map and flatMap? EASY ▾

map applies a transformation to each element and returns a new list of the same size. The result type is List<R>.

flatMap applies a transformation that returns a collection for each element, then flattens all results into a single list. Result type is still List<R> but typically larger than input.

val words = listOf("Hello", "World")

words.map { it.toList() }
// [[H,e,l,l,o], [W,o,r,l,d]] ← list of lists

words.flatMap { it.toList() }
// [H,e,l,l,o,W,o,r,l,d] ← flat list
Q What is the difference between fold and reduce? EASY ▾

reduce — uses the first element as the initial accumulator. Throws UnsupportedOperationException on empty collections.

fold — takes an explicit initial value. Works on empty collections (returns initial value). Can also produce a different type than the input.

Key interview answer: prefer fold in production. It is always safe, and its initial value makes the intent explicit. Use reduceOrNull if you must use reduce.

Q When should you use Sequence instead of a List? MEDIUM ▾

Use Sequence when:

1. You have a large dataset (>1000 items) and chain multiple operations — Sequence avoids creating intermediate lists at each step.

2. You need early termination — operators like take, first, takeWhile stop processing as soon as the condition is met.

3. You need an infinite sequence via generateSequence or sequence { } builder.

Do NOT use Sequence for small lists — the overhead of the iterator chain makes it slower than a regular Collection for small sizes.

Q What is the difference between groupBy and partition? MEDIUM ▾

partition splits a collection into exactly two groups based on a boolean predicate, returning a Pair<List<T>, List<T>>.

groupBy splits into any number of groups based on a key selector, returning a Map<K, List<T>>.

Use partition for boolean splits (active/inactive). Use groupBy for categorical grouping (by department, by status enum).

Q What is the difference between any(), all(), and none()? What happens on empty lists? MEDIUM ▾

any { } — returns true if at least one element matches. Short-circuits on first match. On empty list → false.

all { } — returns true if all elements match. Short-circuits on first non-match. On empty list → true (vacuous truth).

none { } — returns true if no elements match. On empty list → true.

Interview trap: emptyList<Int>().all { it > 0 } returns true — this surprises most candidates!

Q What is the difference between associateBy, associateWith, and associate? MEDIUM ▾

associateBy { key } — lambda picks the key. The element itself becomes the value. Returns Map<K, T>.

associateWith { value } — the element is the key. Lambda picks the value. Returns Map<T, V>.

associate { element → key to value } — full control of both key and value. Returns Map<K, V>.

val users = listOf(User(1, "Alice"), User(2, "Bob"))
users.associateBy { it.id }       // {1=User, 2=User}
users.associateWith { it.name }   // {User=Alice, User=Bob}
users.associate { it.id to it.name } // {1=Alice, 2=Bob}
Q How does distinct() differ from converting to a Set? MEDIUM ▾

Both remove duplicates, but distinct() preserves insertion order and returns a List.

Converting to a HashSet does NOT guarantee order. Converting to LinkedHashSet preserves order but produces a Set, not a List.

distinctBy { selector } is more powerful — it removes duplicates based on a computed key, keeping the first occurrence.

Q What does getOrPut do and why is it useful? MEDIUM ▾

getOrPut(key) { defaultValue } — if the key exists, returns the existing value. If not, inserts the default value and returns it. This is atomic in a single call.

Classic use: building an adjacency list or grouping without an explicit null check:

// Build adjacency list for a graph
val adj = mutableMapOf<Int, MutableList<Int>>()
edges.forEach { (u, v) ->
    adj.getOrPut(u) { mutableListOf() }.add(v)
    adj.getOrPut(v) { mutableListOf() }.add(u)
}
Q Explain the difference between filter → map vs mapNotNull. Which is preferred? HARD ▾

filter { it != null }.map { it!! } — two passes over the collection, and you need !! (unsafe non-null assertion) which is a code smell.

mapNotNull { } — single pass, type-safe, idiomatic Kotlin. The compiler knows the result is non-null. Always prefer this.

val strs = listOf("1", "abc", "3", "xyz")

// ❌ Bad: two passes + unsafe !! 
strs.map { it.toIntOrNull() }.filter { it != null }.map { it!! }

// ✅ Good: single pass, type-safe
strs.mapNotNull { it.toIntOrNull() }  // [1, 3]
Q What is runningFold / scan and when is it useful? HARD ▾

runningFold (also called scan in some languages) is like fold but returns all intermediate accumulator values, not just the final result.

Useful for: prefix sums, running totals, cumulative analytics, undo history stacks.

val sales = listOf(100, 200, 150, 300)

// Cumulative sales per month
sales.runningFold(0) { acc, s -> acc + s }
// [0, 100, 300, 450, 750]

// Running max — peak value at each point
sales.runningReduce { acc, s -> maxOf(acc, s) }
// [100, 200, 200, 300]
Q Is Kotlin's listOf() truly immutable? Can it be mutated? HARD ▾

No — it is read-only, not truly immutable. listOf() returns a List<T> interface which has no mutation methods. However the underlying implementation is often a java.util.Arrays$ArrayList which IS mutable.

You can bypass the read-only restriction via an unsafe cast:

val list = listOf(1, 2, 3)
(list as MutableList<Int>).add(4)  // 💥 UnsupportedOperationException!
// (This particular impl does throw, but it's undefined behaviour)

// For truly immutable: use Guava's ImmutableList or
// Collections.unmodifiableList() or copy-on-write patterns

P1 Find the most frequent element in a list

Given listOf(1, 2, 3, 2, 1, 2, 4), return the element that appears most often. If tie, return any.

Solution.kt
fun mostFrequent(list: List<Int>): Int? {
    return list
        .groupingBy { it }
        .eachCount()              // Map<Int, Int> frequency map
        .maxByOrNull { it.value }  // entry with highest count
        ?.key
}

// Alternatively with groupBy:
fun mostFrequent2(list: List<Int>) =
    list.groupBy { it }
        .maxByOrNull { it.value.size }
        ?.key

P2 Group anagrams together
MAPSORTED

Given listOf("eat","tea","tan","ate","nat","bat"), group all anagrams together into a List<List<String>>.

Solution.kt
fun groupAnagrams(words: List<String>): List<List<String>> {
    return words
        .groupBy { word ->
            word.toCharArray().sorted().joinToString("")
        }           // sort chars → same key for anagrams
        .values     // Map values = groups
        .toList()
}

// [[eat,tea,ate], [tan,nat], [bat]]

P6 Two-sum using a Map (O(n) solution)
MAPALGORITHM

Given listOf(2, 7, 11, 15) and target = 9, return indices of two numbers that add up to target. Must be O(n).

Solution.kt
fun twoSum(nums: List<Int>, target: Int): Pair<Int, Int>? {
    val seen = mutableMapOf<Int, Int>()  // value → index
    for ((i, num) in nums.withIndex()) {
        val complement = target - num
        val j = seen[complement]
        if (j != null) return j to i
        seen[num] = i
    }
    return null
}

twoSum(listOf(2,7,11,15), 9)  // (0, 1)

// Time: O(n) — one pass  |  Space: O(n) — the map

    return userIds
        .chunked(50)                     // [[id1..50], [id51..100], ...]
        .flatMap { batch ->
            api.fetchUsers(batch)        // List<User> per batch
        }
}

P9 Find all pairs that sum to a target
SEQUENCEFILTERCOMBINATIONS

Given listOf(1, 2, 3, 4, 5) and target = 6, find all unique pairs (a, b) where a + b == target and a < b.

Solution.kt
fun findPairs(nums: List<Int>, target: Int): List<Pair<Int,Int>> {
    val set = nums.toHashSet()
    return nums
        .asSequence()
        .filter { n ->
            val complement = target - n
            complement > n && complement in set
        }
        .map { n -> n to (target - n) }
        .toList()
}

findPairs(listOf(1,2,3,4,5), 6)
// [(1,5), (2,4)]
P10 Implement word frequency counter (interview classic)
MAPSORTCLASSIC

Given a string "the quick brown fox jumps over the lazy dog the", return the top 3 most frequent words in descending order.

Solution.kt
fun topKWords(text: String, k: Int): List<String> {
    return text
        .split(" ", "\n", "\t")     // tokenise
        .map { it.lowercase().trim() }  // normalise
        .filter { it.isNotBlank() }     // remove empties
        .groupingBy { it }
        .eachCount()                     // frequency map
        .entries
        .sortedByDescending { it.value } // sort by count
        .take(k)
        .map { it.key }
}

val text = "the quick brown fox jumps over the lazy dog the"
topKWords(text, 3)  // [the, quick, brown]

INTERVIEW GOTCHAS
Common traps that trip candidates
Gotchas.kt 
// ── 1. reduce on empty list throws ────────────────────────
emptyList<Int>().reduce { a, b -> a + b }  // 💥 UnsupportedOperationException
emptyList<Int>().reduceOrNull { a, b -> a + b }  // ✅ null

// ── 2. all{} on empty list = true (vacuous truth) ─────────
emptyList<Int>().all { it > 0 }   // true ← surprising!
emptyList<Int>().none { it > 0 }  // true
emptyList<Int>().any { it > 0 }   // false

// ── 3. subList is a VIEW, not a copy ──────────────────────
val m = mutableListOf(1, 2, 3, 4)
val sub = m.subList(1, 3)  // [2, 3] — backed by m
m.add(5)                   // modifying m invalidates sub!
sub[0]                     // 💥 ConcurrentModificationException

// ── 4. Sequence is lazy — nothing runs without terminal op ─
val seq = listOf(1, 2, 3).asSequence()
    .map { println("map $it"); it * 2 }
// Nothing printed yet — need a terminal op:
seq.toList()  // NOW it prints: map 1, map 2, map 3

// ── 5. distinctBy keeps FIRST occurrence only ──────────────
listOf("Alice", "alice", "ALICE")
    .distinctBy { it.lowercase() }  // [Alice] — keeps first

// ── 6. + operator on List creates NEW list (non-destructive)
val a = listOf(1, 2)
val b = a + 3  // new list [1, 2, 3]; a is unchanged

// ── 7. zip stops at shorter list ──────────────────────────
listOf(1, 2, 3).zip(listOf("a", "b"))
// [(1,a), (2,b)] — 3 is dropped!

// ── 8. associateBy on duplicate keys: LAST wins ────────────
listOf(User(1,"Alice"), User(1,"Bob"))
    .associateBy { it.id }  // {1=User(Bob)} — Alice is GONE

// ── 9. forEach vs map — don't use map for side effects ────
listOf(1,2,3).map { println(it) }  // ❌ returns List<Unit>, wastes memory
listOf(1,2,3).forEach { println(it) } // ✅ correct for side effects
✦ Final interview tip: When asked to solve a collection problem, always clarify: (1) Can the input be empty? (2) Are there duplicates? (3) What's the expected time complexity? Mentioning these shows senior-level thinking even before writing a line of code.
